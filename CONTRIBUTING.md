# Contribution Standard

1. Link the change to a product risk, defect, or architecture decision.
2. Keep the branch focused on one coherent outcome.
3. Add the lowest-cost effective verification first.
4. Preserve test independence and synthetic data ownership.
5. Update traceability and documentation when risk coverage changes.
6. Run `npm run format:check`, `npm run lint`, `npm run typecheck`, and the affected tests.
7. Include commands, results, evidence, and known limitations in the pull request.
8. Do not merge unexplained failures or permanent quarantines.
