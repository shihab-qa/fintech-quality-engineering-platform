# Portfolio Evidence Checklist

A reviewer should be able to verify engineering depth without relying on claims alone.

- CI status visible on the default branch
- Pull request quality gate with separate static, API, and browser jobs
- Nightly regression history
- HTML report and failure artifacts from an intentionally demonstrated test failure in a non-main branch
- Traceability from product risk to automated evidence
- API runtime contract validation
- Independent test data and cleanup
- Cross-browser and mobile execution
- Accessibility evidence attachment
- OpenAPI contract and architecture decision records
- Tagged release with release notes and known limitations
